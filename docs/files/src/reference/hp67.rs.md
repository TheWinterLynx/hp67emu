# `src/reference/hp67.rs`

## Purpose

Composes the Woodstock semantic machine, HP-67 RAM map and CRC reference peripheral into a model that can execute HP-67 microcode instruction by instruction.

## Why it exists

A Woodstock CPU reference alone is insufficient for the HP-67 because CRC flag opcodes override otherwise-unused special instructions and the card reader appears at two RAM-like addresses. The integrated model provides the architectural result that the future electrical machine must reproduce without making the semantic model the final fidelity path.

## Relationships

Exported by `src/reference/mod.rs`. It wraps `reference::woodstock::ReferenceMachine`, uses `reference::crc::CrcReference`, and can fetch from `reference::rom::RomImage`. Instruction-boundary snapshots can be taken from its `core` with `reference::snapshot`.

## Responsibilities

Apply the HP-67 page-zero implicit bank reset before ROM fetch, give CRC opcodes priority over generic CPU specials, route CRC flag-test results into ACT S3, redirect CRC read/write RAM ports away from ordinary RAM, preserve THEN-GOTO target-word semantics, expose the RUN/W-PRGM switch as CRC external flag 1, and provide card insertion/completion helpers.

## Implementation

`step_word()` first distinguishes a pending THEN-GOTO target from a real opcode. CRC flag words are executed by advancing the Woodstock boundary with a semantic NOP and then applying the external controller effect; successful CRC tests OR ACT status S3. Ordinary Woodstock words are delegated to `ReferenceMachine::step_word()`. After CPU RAM operations, accesses resolving to `0x99` or `0x9b` are redirected to CRC write/read semantics. `step()` fetches from a `RomImage` and enforces Hawkeye's implicit bank-zero rule on page 0.
