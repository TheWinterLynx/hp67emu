# `src/hp67.rs`

## Purpose
Owns the remaining UI mechanical controls and a UI-local HP-67 structural machine whose LED state is derived from machine state, real firmware and ACT-owned serial behavior.

## Why it exists
The frontend must expose hardware-derived behavior without formatting numbers or constructing display bytes. The photographed calculator begins in the physical OFF switch position: no firmware time advances and no LED emission is rendered until the user moves power to ON. Startup zeroes and the final `0.00` then emerge from ACT state, shared IS transport, ROM0 decoding and downstream cathode selection.

## Relationships
`Hp67LiveMachine` uses the reusable `Hp67ArchitecturalMachine`, `ActSerialEndpoint`, shared display/fetch word transport, ROM0 decoder and 1820-1749 structural cathode driver. Firmware remains external through `RomCorpus`. `app.rs` advances the machine with elapsed wall-clock time only while `Hp67State.power_on` is true, and `panel.rs` consumes only raw segment masks.

## Responsibilities
Default the mechanical power switch to OFF; load exactly 5120 normalized external firmware words; keep the display unclaimed during the pre-SYNC reset interval after an actual OFF→ON transition; bind each executing firmware word to the same complete b0..b55 structural cycle that fetches its successor; update each physical display slot only from ACT-owned bit serialization; consume ROM0 STR and ACT RCD downstream; and never synthesize startup or idle display values.

## Implementation
`Hp67State::default()` starts with `power_on=false`. `app.rs` does not call `advance()` while the switch is OFF. An OFF→ON transition clears host timing and calls `reset_power_on()`, so reset hold, natural zero emission and firmware boot begin from cycle zero only when power is actually switched on.

At each firmware cycle the prefetched word becomes the executing word. Before architectural fallback semantics are applied, the live machine captures the pre-execution `ActInstructionState` and calls `ActSerialEndpoint::begin_execution()`. The following shared structural word advances that same execution through all b0..b55 coordinates. The machine verifies completion before accepting the next executing word. Reaching the no-key idle checkpoint no longer short-circuits the current structural word: the final active instruction first reaches b55, then the live machine enters `Idle`.

The display remains on the same transport. `ActSerialEndpoint` owns the 1..15 display phase, ROM0 owns STR and ACT owns the coarse RCD boundary. The cathode cannot choose what ACT emits. Architectural reset A=B=0 therefore naturally releases the display bits seen by ROM0 as zero under the weak-low IS bias.

The remaining ACT fidelity boundary is narrower but explicit: instruction execution now has the correct full-word lifetime, while internal A/B/C/ALU/carry mutations still use instruction-boundary semantics until evidence fixes their intra-word commit timing. No PHI edge is fabricated by this slice.
