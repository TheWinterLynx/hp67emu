# `src/hp67.rs`

## Purpose
Owns the remaining UI mechanical controls and a UI-local HP-67 structural machine whose LED state is derived from machine state, real firmware and ACT-owned serial display output.

## Why it exists
The frontend must expose hardware-derived behavior without formatting numbers or constructing display bytes. The photographed calculator should also begin in the physical OFF switch position: no firmware time advances and no LED emission is rendered until the user moves power to ON. Startup zeroes and the final `0.00` must then emerge from ACT state, shared IS transport, ROM0 decoding and downstream cathode selection.

## Relationships
`Hp67LiveMachine` uses the reusable `Hp67ArchitecturalMachine`, `ActSerialEndpoint`, shared display/fetch word transport, ROM0 decoder and 1820-1749 structural cathode driver. Firmware remains external through `RomCorpus`. `app.rs` advances the machine with elapsed wall-clock time only while `Hp67State.power_on` is true, and `panel.rs` consumes only raw segment masks.

## Responsibilities
Default the mechanical power switch to OFF; load exactly 5120 normalized external firmware words; keep the display unclaimed during the pre-SYNC reset interval after an actual OFF→ON transition; after firmware fetch begins, update each physical slot only from ACT-owned bit serialization across the shared word; detect the firmware's real display-off/toggle instructions; consume ROM0 STR and ACT RCD only in the downstream cathode model; and never synthesize a startup or idle display value.

## Implementation
`Hp67State::default()` starts with `power_on=false`. The live machine object may already exist as inert state, but `app.rs` does not call `advance()` while the switch is OFF. An OFF→ON UI transition clears the host timing accumulator and calls `reset_power_on()`, so the observed reset hold, natural zero flash and firmware boot begin from cycle zero only when the user powers the calculator on.

`transport_fetch_word()` does not read or pass a cathode slot into the transport. `ActSerialEndpoint` owns the 1..15 display phase internally. `run_structural_display_fetch_cycle()` returns the ROM0-owned `str_event` and ACT-owned `rcd_falling` event after the shared 56-bit word completes. The UI decodes the ROM0-observed byte for `str_event.scan_slot`, then `CathodeDriver1820_1749::apply_control_edges()` consumes the STR/RCD events and validates downstream phase. The cathode cannot choose what the ACT emits.

The architectural reset A=B=0 therefore naturally releases all eight wired-high display bits, which ROM0 observes as zero under the weak-low bias. After the first explicit firmware display-control opcode, `display_enable` governs emission normally. The transport now reads A/B contents at each b0..b7 bit cell rather than snapshotting the two source nibbles at word start. Architectural A/B still remain instruction-boundary state for now; true intra-word register/ALU evolution is the next M3 fidelity step.
